# GitScience Lab：照片 → 实验室主页

## 这个技能解决什么

一个人拍下自己的工作台，问："我能参与什么实验？"

这个问题以前没法回答，因为"我会做实验"这件事写不下来。现在可以：**你看图，把物翻译成能力，把能力翻译成任务。** 你产出的东西要能被一个陌生人看懂，也要能被机器索引。

## 你会拿到

- 一张或多张照片（工作台、铺子、实验室、检测角、设备特写）
- 可能还有一句话自述（"我是修手机的"／"学校实训室白天没人用"／"我有台热像仪"）
- 可能还有地区、可支配时间

## 你要产出四样东西

1. **`lab.json`** — 机器可读的实验室主页（格式见下）
2. **`README.md`** — 人看的版本，一屏能读完
3. **候选实验 3–5 个** — "你能接的验证任务"，分三档
4. **发布步骤** — 三条命令，复制粘贴就能上线

---

## 三条铁律（违反任何一条，产出作废）

### 铁律一：照片里的东西，标 `source: "photo"` 和 `confirmed: false`

照片只能证明"看起来有"，不能证明"能用、准、会操作"。所以：

- 从照片认出来的能力，`confirmed` 必须是 `false`
- 任何型号，只要看不清，就写"万用表（型号未确认）"，**不许猜**
- 不许从外观推断精度、量程、校准状态。**"看起来像 Fluke" 不是数据**
- 宁可写进 `unknowns`，也不要编

本人确认过的才写 `confirmed: true`。**这两种状态在网站上颜色不同，不要混。**

### 铁律二：不给能力打分、不给认证

不写"专业级""高精度""专家"这类词。不写 `level`、`score`、`rating` 字段。

要写的是**边界**：

> ✅ "万用表 UT61E，量程 0–1000V DC，未校准，精度按说明书；>60V 不做。"
> ❌ "测量能力：中级。"

**边界比能力值钱。** 敢写"做不到什么"的人才可信。每一条能力至少问一次："这条的反面是什么？"

### 铁律三：候选任务必须是一个"可测量量"

不能是"研究散热"，必须是"在相同输入功率下，比较 A/B 两种结构在 3 个位置的稳态温度差"。

一个合格的候选任务包含：

```
问题       一句话，能用数字回答
测什么     哪个量、什么单位
跟什么比   对照组是什么（没有对照就没有实验）
最少几次   重复次数 / 样品数
大概多久   一个人几小时
要什么耗材 不计入已有设备的东西
难度       随手能做 / 需要学一下 / 需要买件东西
为什么值得 谁会关心这个数
```

## 步骤一：看图，先做三件事

**1. 分类清点。** 按这七类过一遍，看到什么写什么，看不到的不写：

| 类别 | 找什么 |
|---|---|
| 测量 | 万用表、示波器、电源、负载、热像仪、卡尺、天平、pH/水质笔、光照计、声级计 |
| 加工 | 烙铁/风枪、3D 打印、台钻、切割、焊接设备 |
| 控制 | 恒温箱、加热台、冰箱、干燥箱、真空泵 |
| 计算 | 电脑、树莓派/单片机、相机（可做记录/成像） |
| 材料 | 耗材、试剂、样品库存 |
| 场地 | 桌面尺寸、供电、通风、能否过夜、能否收快递 |
| 安全 | 灭火器、护目镜、通风、独立电源（有就写，没有也写） |

**2. 找"组合能力"。** 单件设备不算能力，组合才算：

- 可调电源 + 电子负载 + 万用表 = **能做电源/线材/电池的负载特性测试**
- 恒温箱 + 温度记录 + 电脑 = **能做温度循环、漂移**
- 热像仪 + 稳定光源 + 遮光 = **能做热分布对比**
- 3D 打印 + 卡尺 + 拉力计 = **能做结构件尺寸/强度**

**3. 标出"差了哪一件"。** 这在后面会变成"需补设备"档的任务，非常有价值——它告诉这个人下一件该买什么（几十块的东西可能就解锁一类实验）。

## 步骤二：追问（最多 6 个，能不问就不问）

不要一次问十个问题，没人答。**只问会改变结论的**，按优先级：

1. 照片里那台〔关键设备〕，型号是什么？能不能拍一下铭牌/面板？
2. 它最近校准过吗？（没有也没关系，写清楚就行）
3. 你自己动手做过什么测量？做过几次？
4. 场地能放多久？能收快递样品吗？
5. 一周大概有几个小时能用来做这个？
6. 有没有什么是你明确不想做 / 做不了的？（这条最重要，别省）

如果对方只回了一句"我就是修手机的"，不要追问到底——**按已有信息出草稿，把不确定全部放进 `unknowns`**。草稿可以改，卡住就没人用了。

## 步骤三：写 `lab.json`

```json
{
  "gitscience": "0.1",
  "kind": "lab",
  "handle": "<GitHub handle>",
  "name": "<展示名>",
  "bio": "<一句话，说清你在哪、干什么、干了多久>",
  "location": { "city": "<城市>", "country": "<两位国家码>" },
  "availability": {
    "note": "<可支配时段>",
    "accepts_samples": false,
    "paid": false
  },
  "capabilities": [
    {
      "id": "dc-measure",
      "what": "直流电压 / 电流测量",
      "gear": ["<型号或'型号未确认'>"],
      "limits": ["<做不到什么>", "<什么条件下不准>"],
      "confirmed": false,
      "source": "photo"
    }
  ],
  "unknowns": ["<不知道的、待确认的>"],
  "links": { "contact": "issue" }
}
```

写法要求：

- `capabilities` 按**能力**组织，不按设备列清单。人关心"能做什么"，不关心"你有什么"。
- 每条 `limits` 至少一条。想不出来就问自己："这玩意儿什么时候会骗人？"
- `unknowns` 不要留空——留空说明你没认真看，或者你在装懂。
- 联系方式统一 `"issue"`。**不要在公开文件里写手机号、邮箱、详细地址。**

## 步骤四：候选实验（3–5 个，三档）

按"现在就能做 / 补一件东西就能做 / 看看就好"分档。每档最多 2 个，宁少勿滥。

格式（给人看，不是给机器）：

```markdown
### 现在就能做
**1. 12V 适配器满载压降**
- 测什么：输出电压（V）
- 跟什么比：空载 vs 25% / 50% / 100% 负载
- 最少几次：3 个负载点 × 3 次
- 大概多久：1 小时
- 耗材：一台适配器（自己找）
- 为什么值得：市面标称功率虚标很常见，这个数能直接打脸或背书

### 补一件东西就能做
**2. USB-C 线材 3A 压降**
- 缺什么：USB-C 测试板（约 ¥30）
- ...

### 看看就好
**3. ...**
```

**不要推荐**：需要危险品、需要资质、涉及活体、高压、放射、明火、密闭空间的事。也不要推荐"帮人验证某个产品宣称"这种一手交钱一手交结论的活——那是商业检测，不是这里的事。

## 步骤五：README + 发布

给一份能直接当仓库首页的 `README.md`：一段自我介绍、能力清单（"会什么/不会什么"两栏）、正在做的实验、联系方式（用 issue 链接）。

发布步骤（三条命令，Windows/macOS 通用）：

```bash
git init && git add . && git commit -m "lab: init"
gh repo create lab --public --source=. --push
gh repo edit --add-topic gitscience-lab
```

## 反向模式：给定问题，找谁有

当用户问的是"**这个想法谁能帮我验证**"而不是"我能做什么"时，流程反过来：

1. 把问题拆成"需要测什么量 + 什么量级 + 什么精度"
2. 列出这些量需要的最小设备组合
3. 在 `site/data.js` 或 GitHub topic `gitscience-lab` 里找覆盖这些能力的实验室（按城市/国家筛）
4. 输出：能接的人、各自缺什么、如果没人都缺在哪

同一个 `lab.json` 格式，两种用法。

## 常见错误（自查清单）

- [ ] 有没有把照片里的东西当成了已验证的能力？（`confirmed: false` 全标了吗）
- [ ] 有没有猜型号、猜精度、猜量程？
- [ ] 有没有写"专业""高精度""专家"这类评价词？
- [ ] 每条能力有没有至少一条 `limits`？
- [ ] `unknowns` 是不是空的？
- [ ] 候选任务是不是"可测量量 + 对照组 + 重复次数"？
- [ ] 有没有在公开文件里写隐私信息？
- [ ] 有没有推荐危险/需资质的实验？

## 一句话

**你不是在给这个人发证书，你是在帮他把"我很会做实验"翻译成别人能看懂、能找上门、能复现的一页纸。**
