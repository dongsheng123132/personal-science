# 用 AirPods 的头部运动数据控制鼠标指针（Linux 版）

> 你能亲手验证：在 Linux 上不经过任何 Apple 设备，直接读到 AirPods 的陀螺仪/加速度计数据，并把它变成能动的鼠标指针。

| | |
|---|---|
| **需要** | 一台装了 Linux 的电脑（蓝牙可用）；一副支持头部追踪的 AirPods（具体型号待核实——MousePods 项目页会写明兼容列表，动手前先去查）；Python 3；蓝牙工具（`bluetoothctl`，多数发行版自带）；MousePods 项目源码（GitHub，免费） |
| **时间** | 一个下午到一天（含排错） |
| **花费** | ¥0（假设你已有 AirPods 和电脑；没有的话本实验不做） |
| **难度** | ★★★ |
| **验收** | 做之前写死：① 终端里能连续打印出非零的陀螺仪三轴读数，且**转动头部时至少一个轴的数值变化幅度 > 10 倍静止时的噪声**；② 指针能随头部转动移动，**在 30 秒测试里成功触发 ≥ 10 次位移**；③ 全程没有 Apple 设备参与配对。三条全中算成功。 |

## 为什么值得做

AirPods 的头部追踪数据一直被锁在 Apple 生态里。MousePods 证明了这层锁是协议层的，不是硬件层的——在 Linux 上逆向出数据通道后，传感器就归你了。

这件事的价值不在"用头当鼠标"这个噱头，而在于：**你亲手验证了一个封闭设备的数据可以被第三方读出**。这是可复现的逆向工程，不是看新闻。

## 怎么做

1. **先读项目页**。去 MousePods 的 GitHub 仓库，确认：支持的 AirPods 型号、支持的 Linux 发行版/内核版本、依赖清单。**不要跳过这步**——型号不匹配，后面全白做。
2. **装依赖**。按仓库 README 装 Python 包和蓝牙相关依赖。版本号以 README 为准，本文不写死。
3. **配对**。用 `bluetoothctl` 把 AirPods 连到 Linux。确认 `bluetoothctl info <MAC>` 能看到已连接。
4. **跑数据通道**。先只跑"读传感器"那部分，不接鼠标。目标：终端里刷出陀螺仪/加速度计数值。
5. **验证数据是真的**。静止 10 秒，记下读数波动范围（噪声）。然后缓慢转头，看数值是否明显跳出噪声带。**这一步就是验收标准①。**
6. **接鼠标**。启用 MousePods 的鼠标映射，设定灵敏度。
7. **30 秒测试**。转头，数指针位移次数。**这是验收标准②。**
8. **记录**。把噪声范围、转头时的峰值、30 秒内位移次数写下来。这就是你的实验数据。

## 算一下 / 会看到什么

- **信噪比**：验收标准①要求转头时变化 > 10 倍静止噪声。如果达不到，先怀疑是灵敏度设置太低或传感器没真正激活，而不是"AirPods 坏了"。
- **会看到**：静止时读数在小范围内抖动（这是正常噪声）；转头时某个轴突然大幅偏移，回正后回落。
- **指针行为**：头部转动 → 指针移动，但会有延迟。延迟大小取决于蓝牙轮询率，**具体毫秒数待实测**，别信任何写死的数字。

## 坑

- **型号不对**。不是所有 AirPods 都有头部追踪。买之前/做之前查清楚，这是最容易白干的一步。
- **以为连上蓝牙就等于拿到数据**。普通蓝牙音频连接不暴露运动传感器，MousePods 走的是另一条通道。连上了但读不到数，是正常的中间状态，不是失败。
- **把噪声当信号**。静止时读数本来就在抖。不先测噪声基线，就无法判断转头时的变化是不是真的。
- **Linux 蓝牙栈差异**。不同发行版/内核的 BlueZ 行为不一样，别人的成功命令在你机器上可能报错。以报错为准去查，别硬套。
- **项目更新导致步骤过时**。本文不写死版本号，就是因为这个。以仓库当前 README 为准。

## 安全

- 只用你自己的设备，只读自己设备的传感器数据。
- 不要用这个工具去读别人的 AirPods。
- 逆向工程用于自己设备的互操作是常见做法，但各地法律不同，**商用或分发前请自行核实当地规定**。
- 长时间戴耳机做测试，注意音量和时长，别为了实验把耳朵搞坏。
