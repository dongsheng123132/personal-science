# 用旧手机主板做一台遥控飞机的“大脑”

> 你能亲手验证：一块旧安卓手机主板，能不能当遥控飞机的控制板用——用可测量的方式判断它够不够格。

| | |
|---|---|
| **需要** | 旧安卓手机 1 部（能开机、屏幕可碎，型号待核实，需支持 USB OTG）<br>USB OTG 转接线 1 根（待核实接口类型，多为 Micro-USB 或 Type-C）<br>USB 转串口模块 1 个（CH340 或 CP2102 类，价格待核实）<br>Arduino Nano 或同类开发板 1 块（价格待核实）<br>舵机 2 个（9g 类，价格待核实）<br>面包板 + 杜邦线若干<br>万用表 1 个（没有可借，或买最便宜的，价格待核实）<br>电子秤或厨房秤 1 个（称重，家里有就用） |
| **时间** | 一个周末（约 6–8 小时，分两天） |
| **花费** | 目标 ≤ ¥200；OTG 线 + 串口模块 + 开发板 + 舵机是主要开销，具体价格**待核实**，买前先比价 |
| **难度** | ★★☆ |
| **验收** | 做完后同时满足三条：<br>① 手机通过 OTG 能向串口模块**稳定发送数据 ≥ 10 分钟不中断**（串口助手看到连续输出）；<br>② 从“手机发出指令”到“舵机转到目标角度”的**端到端延迟中位数 ≤ 100 ms**（测 20 次取中位数）；<br>③ 整套（手机主板 + 转接 + 开发板 + 2 舵机）**总重 ≤ 150 g**（厨房秤称）。<br>三条全过 = 成功；任一条不过 = 记录实测值，算“部分成功”。 |

## 为什么值得做

旧手机里有 CPU、内存、Wi-Fi、蓝牙、陀螺仪、GPS、摄像头。这些东西单买都不便宜。手机淘汰往往只是因为屏幕碎了或电池老了，主板本身还能跑。

把它当遥控飞机的控制板，本质是问一个问题：**一块现成的、免费的、算力过剩的板子，能不能替代专门买的飞控？**

这个问题有明确的答案，而且答案可以用数字判断——延迟、稳定性、重量。不是“感觉能用”，是“测出来能用/不能用”。

这也是一个很好的“反向工程”练习：你会被迫搞清楚 OTG、串口、供电、接地这些平时被库函数藏起来的东西。

## 怎么做

**第 0 步：先定验收，再动手。**
把上面三条验收标准抄在纸上贴墙上。别做完再想“算不算成功”。

**第 1 步：确认手机还活着。**
充电，开机。能进系统就行，屏幕碎了用 OTG 接鼠标操作，或投屏。记下安卓版本。

**第 2 步：验证 OTG 供电与数据。**
手机接 OTG 线，再接 USB 转串口模块。手机上装一个串口终端 App（应用商店搜“serial terminal”，具体 App 待核实，选评分高的）。
用杜邦线把串口模块的 TX 和 RX **短接**（自环测试）。在 App 里发字符，看是否原样收到。
收到 = OTG 数据通路通。收不到 = 先解决这一步，别往下走。

**第 3 步：手机 → 开发板。**
串口模块 TX 接开发板 RX，RX 接开发板 TX，**GND 必须共地**。
开发板烧一个最简程序：收到字节就原样回发，并点亮板载 LED。
手机 App 发 “A”，开发板回 “A”，LED 闪。通了。

**第 4 步：开发板 → 舵机。**
舵机信号线接开发板 PWM 脚，电源**单独供**（见「坑」）。烧程序：收到 “0”–“9” 就转到对应角度。
手机发数字，舵机跟着转。

**第 5 步：测延迟（验收②）。**
方法：手机 App 里做一个“按键即发时间戳”的界面（或让 AI 帮你写，见下）。开发板收到后立刻回发。手机记录发出和收到的时间差，除以 2 估算单程。
测 20 次，取中位数。记下来。

**第 6 步：测稳定性（验收①）。**
让手机每 100 ms 发一个字节，连续 10 分钟。串口助手或开发板计数。丢包率记下来。

**第 7 步：称重（验收③）。**
手机主板拆下来（如果能安全拆），或整机称。加转接、开发板、舵机，厨房秤称总重。

**第 8 步：对照验收表，写结论。**
过几条，不过几条，实测值多少。这就是你的实验结果。

## 算一下 / 会看到什么

- **延迟**：手机 App 计时 → USB → 串口 → 开发板 → 回发。这条链上，USB 轮询和安卓调度是大头。**预期单程在几十毫秒量级**，但具体值必须实测，不要信任何人的“应该很快”。
- **丢包**：10 分钟、10 Hz 发送 = 6000 个字节。数一下收到多少。丢包率 = (6000 − 收到数) / 6000。
- **重量**：一块手机主板通常几十克量级（**具体待核实，以你称的为准**）。加转接和开发板，150 g 是个紧的线——这正是要测的原因。
- **结论怎么写**：三条验收全过，写“该方案在延迟/稳定性/重量上满足低速遥控飞机控制链路的最低要求”。有一条不过，写“不满足，瓶颈在 X，实测值 Y，验收线 Z”。

## 坑

1. **舵机电源从开发板取。** 舵机启动电流大，会把开发板拉复位，表现为“程序莫名其妙重启”。舵机电源单独供，**必须共地**。
2. **忘了共地。** 手机、串口模块、开发板、舵机电源，所有 GND 要连在一起。不共地，数据全是乱码。
3. **OTG 线买错。** 有的线只供电不传数据。买前确认是“OTG 数据线”。接口是 Micro-USB 还是 Type-C，**先看你的手机，别猜**。
4. **手机省电策略杀后台。** 安卓会冻结后台 App，串口突然断。测试时把 App 加入“不受限制”名单，关掉电池优化。
5. **把“能亮灯”当成“能用”。** 灯亮只证明通电。延迟和丢包才是验收标准，别提前庆祝。
6. **拆主板拆坏。** 旧手机主板和电池、排线粘得很紧。拆坏了整个实验就没了。**先整机测通，再考虑拆。**
7. **串口波特率不一致。** 手机端和开发板端必须同波特率。对不上就是乱码，很容易误判成“线坏了”。

## 想再往前一步

- **加 IMU**：手机自带陀螺仪，读出来，和开发板的姿态数据对比。这直接关系到能不能做自稳。
- **换无线**：把 USB 线换成手机蓝牙 → 开发板蓝牙模块，测无线延迟。有线 100 ms 不代表无线也 100 ms。
- **做对照实验**：同样的验收标准，测一块几十块的专用飞控板。你的旧手机方案和它差多少？这个对比比单独测手机有意思得多。
- **记录完整数据表**：20 次延迟、6000 次丢包、重量，全部留档。可复现的实验才有价值。

## 安全

- **电池**：旧手机电池可能鼓包。鼓包的电池**不要充电、不要拆、不要挤压**，单独放，按当地规定处理。
- **拆机**：断电再拆。用塑料撬棒，别用金属捅电池。拆的时候别对着脸。
- **焊接**（如果要做）：通风，护目镜，别在易燃物旁边。
- **舵机**：通电测试时手别放在舵机臂行程内，会夹。
- **飞行**：本实验只做**地面台架测试**。真要装机飞，先在空旷无人的场地、低高度、远离人群和电线。**不要在城市、路边、机场附近飞。** 当地法规先查清楚。
- **用电**：所有模块共地后第一次上电，先串万用表看电流，别直接怼。
