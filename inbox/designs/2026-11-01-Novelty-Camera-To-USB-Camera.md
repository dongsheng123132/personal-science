# 把玩具相机改成 USB 摄像头

> 你能亲手验证：一台几十块的玩具相机，能不能变成电脑上能用的摄像头，并且画面延迟和画质在可接受范围内。

| | |
|---|---|
| **需要** | 玩具/一次性数码相机 1 台（型号待核实，需带 USB 口或可拆存储卡）；USB 数据线（接口待核实，常见 mini-USB / micro-USB）；电脑 1 台；免费软件 OBS Studio（版本待核实）或系统自带相机应用 |
| **时间** | 2–4 小时（含调试） |
| **花费** | ¥50–150（相机二手价波动大，待核实） |
| **难度** | ★★☆ |
| **验收** | 电脑能识别到该设备为视频输入源，画面在 OBS 里稳定显示 ≥ 60 秒不黑屏，端到端延迟 ≤ 500 ms（用手机秒表同框对比测） |

## 为什么值得做

玩具相机的卖点是便宜和怪。它通常不能当网络摄像头用，但里面的传感器和 USB 接口往往是标准件。把它接上电脑，你就得到一台"有性格"的摄像头——画质差、色彩怪，但这是你自己验证出来的，不是看别人视频。

更重要的是：这个实验逼你搞清楚三件事——设备到底走什么协议、系统认不认、延迟从哪来。这三件事在任何摄像头项目里都成立。

## 怎么做

1. **拆前先试**：插上 USB，看电脑有没有反应。Windows 看设备管理器，macOS 看"系统信息 > USB"，Linux 跑 `lsusb`。记下 VID/PID。
2. **判断协议**：如果系统直接认成摄像头（UVC），跳到第 4 步。如果只认成存储设备或串口，说明它不是标准摄像头，需要桥接。
3. **桥接方案二选一**：
   - 方案 A：相机能存照片/视频到存储卡 → 用采集卡或手机当采集源（成本上升，待核实）。
   - 方案 B：相机 USB 是数据口 → 查 VID/PID 对应的芯片（待核实），找开源驱动或固件。
4. **在 OBS 里添加视频采集设备**，选到该设备，看画面。
5. **测延迟**：手机开秒表，和相机画面同框，截图对比两个时间差。
6. **测稳定性**：录 60 秒，回放看有没有黑屏、花屏、掉帧。

## 算一下 / 会看到什么

- **分辨率**：玩具相机常见 640×480 或更低（待核实）。如果 OBS 里只能选到 320×240，不算失败，记下来就行。
- **帧率**：目标 ≥ 15 fps。低于 10 fps 画面会明显卡顿。
- **延迟**：USB 摄像头典型 100–300 ms。超过 500 ms 就算验收不通过。
- **稳定性**：60 秒内黑屏次数应为 0。出现 1 次以上，记下发生时间点，方便排查。

## 坑

- **把"能充电"当成"能传数据"**：很多玩具相机的 USB 口只供电。插上没反应先别拆，换根线、换台电脑再试。
- **VID/PID 查不到**：便宜设备的芯片可能是白牌，网上资料少。这时候别硬猜，直接记录现象。
- **OBS 认不到但系统认得到**：可能是驱动问题，也可能是设备只输出 MJPEG 而 OBS 默认设置不匹配。先换格式再换驱动。
- **延迟测量方法错**：用两个屏幕对比会引入额外延迟。必须同框拍摄。
- **拆机拆坏排线**：玩具相机内部排线很脆，拆之前拍照记录走线。

## 想再往前一步

- 给相机加一个 3D 打印外壳，做成桌面摄像头。
- 用 OBS 的滤镜链把画质"救"回来（锐化、降噪、色彩校正），记录前后对比。
- 如果相机支持存储卡，试试定时拍照 + 电脑端自动同步，做成延时摄影。

## 安全

- 拆机前拔掉 USB 和电池。
- 不要用金属工具直接戳电路板，先放电。
- 通电测试时手不要碰裸露电路。
- 如果相机有锂电池，不要刺穿、不要短路、不要加热。
- 电脑 USB 口供电有限，不要外接大功率设备到同一 hub。
