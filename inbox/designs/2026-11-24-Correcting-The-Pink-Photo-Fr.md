# 修正手机相机的“粉红照片”：用一张灰卡验证白平衡

> 你能亲手证明：手机拍出的偏色照片，可以用一个已知中性灰的参照物 + 一个固定公式修正回来，并且修正后的色偏可以被量化地测出来。

| | |
|---|---|
| **需要** | 一部能拍照的手机（任意型号）；一张中性灰卡（摄影灰卡，18% 灰，型号待核实；买不到可用一张纯白打印纸 + 一张纯黑卡纸做近似，精度会下降）；一个能读像素 RGB 值的软件（手机端如“Color Grab”类取色 App，桌面端 GIMP 或 Python + Pillow，具体版本待核实）；一张白纸做背景；室内稳定光源（白天窗边或一盏台灯，避免混合光） |
| **时间** | 2–3 小时（含拍照、取数、算、复拍） |
| **花费** | ¥0–80（灰卡是大头，价格待核实；不买灰卡则接近 ¥0） |
| **难度** | ★★☆ |
| **验收** | 修正前，灰卡区域 R 与 B 通道均值之差 \|R−B\| ≥ 15（0–255 刻度）；用你算出的增益修正后，同一区域 \|R−B\| ≤ 5，且 G 通道变化不超过 ±10%。两个条件同时满足才算成功。 |

## 为什么值得做

手机相机被改装（换镜头、拆滤光片、改固件）后，白平衡会失准，照片整体发粉/发绿。这是相机 hacking 社区的常见问题。它的本质不是“玄学”，是一个可测的通道增益问题：传感器三个通道对同一中性灰的响应不一样，你只要测出偏差、算出增益、乘回去，颜色就回来了。

这个实验的价值在于：它把“看起来好点了”换成“R 和 B 的差从多少降到多少”。你做完会得到一个属于你自己那台手机的修正系数，而不是网上抄来的。

## 怎么做

1. **固定一切能固定的。** 手机架稳（用书堆或三脚架），关掉自动白平衡（能关就关；关不掉就记下它每次的设定），关闪光灯，关 HDR。光源固定，别中途换灯或拉窗帘。
2. **拍参照。** 把灰卡放在白纸背景中央，占画面中间约 1/3。拍一张。这张叫“原图”。
3. **取数。** 用取色软件在原图灰卡中心取一个区域（不要取边缘），读出该区域 R、G、B 的平均值。记下来。重复取 3 个不同位置，取平均，减少噪声。
4. **算增益。** 以 G 为基准（通常 G 最准）：
   - 增益_R = G / R
   - 增益_B = G / B
   保留 3 位小数。
5. **修正。** 用任意能调通道曲线的软件（GIMP 的 Colors→Curves 分通道，或 Python + Pillow 逐像素乘增益并截断到 0–255），把原图每个像素的 R 乘增益_R、B 乘增益_B。存成“修正图”。
6. **复测。** 对修正图的同一灰卡区域重新取 R、G、B 平均值，算 \|R−B\|。
7. **对照验收标准。** 修正前 \|R−B\| 和修正后 \|R−B\| 都记进表里。达标就是成功；不达标看「坑」。

## AI 可以怎么帮你

1. 帮你把步骤写成可执行脚本。
   > “我有一个手机拍的照片，已知灰卡区域平均 RGB 是 (R=210, G=180, B=150)。请写一段 Python（Pillow）代码：以 G 为基准计算 R、B 通道增益，对整张图逐通道相乘并截断到 0–255，保存为新文件。要求打印出两个增益值。”

2. 帮你判断取数是否可信。
   > “我在同一张照片的灰卡上取了 3 个区域，RGB 分别是 (210,180,150)、(205,178,148)、(215,182,153)。这些值的一致性够不够用来算白平衡增益？如果不够，可能是什么原因？给我 3 条排查建议。”

3. 帮你解释失败原因。
   > “我按 G/R 和 G/B 算了增益并修正，但修正后灰卡的 R 和 B 还是差 12（目标 ≤5）。可能的原因有哪些？按可能性从高到低排，每条给一个我能在家做的验证方法。”

4. 帮你把结果写成可复现记录。
   > “帮我把这个实验整理成一张记录表：列包括拍摄条件、灰卡原始 RGB、增益_R、增益_B、修正后 RGB、修正前后 \|R−B\|、是否达标。用 Markdown 表格，留空让我填。”

5. 帮你区分“白平衡错”和“通道饱和”。
   > “我的灰卡原始读数是 (255, 180, 150)。这还能用 G/R 算增益吗？如果不能，说明为什么，并告诉我拍摄时该怎么改条件重拍。”

## 算一下 / 会看到什么

假设你测到灰卡平均 RGB = (210, 180, 150)。

- 修正前：\|R−B\| = \|210−150\| = **60**（远超 15，说明偏色明显）。
- 增益_R = 180/210 ≈ **0.857**；增益_B = 180/150 = **1.200**。
- 修正后理论值：R = 210×0.857 ≈ 180，B = 150×1.200 = 180，G 不变 = 180。
- 修正后 \|R−B\| ≈ **0**，远小于 5，达标。

实际会因为取数噪声、软件截断、光源不均，修正后不会正好是 0，落在 0–5 之间就算成功。你会看到：粉色调消失，白纸背景变回中性白，灰卡三通道数值靠拢。

## 坑

- **灰卡不灰。** 打印纸偏蓝、卡纸偏暖，都会让你的“基准”本身带色偏。这是最大的误差源。买真灰卡，或至少用同一张纸拍一张、再拿它当参照，前后一致。
- **通道饱和。** 任一通道读到 255 或 0，增益公式就失效（信息已丢）。拍摄时降低曝光，让灰卡读数落在 60–200 之间。
- **混合光源。** 窗光 + 台灯同时照，白平衡本身就不一致，修正系数没有意义。只用一种光源。
- **自动白平衡偷偷改。** 手机每张都重算白平衡，你的“原图”和“复拍”条件不同。能关就关，不能关就同一次连拍。
- **取到边缘或反光。** 灰卡边缘有阴影、表面有反光，读数会偏。只取中心平整区域。
- **只修一张图不算验证。** 必须用同一组增益去修“原图”并复测，才算闭环。

## 想再往前一步

- 用同一组增益去修一张**彩色**照片，看肤色和天空是否自然——检验系数是否只对灰卡有效。
- 在不同色温光源下各做一遍，画出“光源色温 vs 增益”的小表，看你的手机偏差是否随光源变化。
- 把增益写进相机 App 的自定义白平衡（如果设备支持），做到“拍出来就对”，不用后期。

## 安全

- 全程无危险操作。不拆机、不接电、不改固件。
- 台灯别靠太近烤到手机或纸张；电线别绊脚。
- 用三脚架时确认锁紧，防止手机跌落。
- 若你之前已改装过手机（拆滤光片等），本实验只做软件修正，不要求你再拆一次；任何进一步拆机不在本页范围内。
