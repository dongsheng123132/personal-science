# 伽利略斜面：亲手量出"加速度"

> 让小球从斜面滚下，用手机慢动作逐帧记位置。你会看见 `s` 和 `t²` 成正比。

| | |
|---|---|
| **需要** | 长木板或晾衣杆（1–2 m）、小球（钢珠/玻璃弹珠）、手机（支持 120/240fps）、卷尺、胶带 |
| **时间** | 1 小时（含分析） |
| **花费** | ¥0–20 |
| **难度** | ★★☆ |
| **验收** | 拟合 `s = ½at²` 的 R² > 0.99，且 `a` 与理论值偏差 < 10% |

## 为什么值得做

1604 年，伽利略用斜面"稀释"重力，才第一次量出匀加速运动。他没有高速摄影，用的是音乐节拍和水钟。

你有 240fps 的手机——同一个实验，精度高一个数量级。而且这一次，**AI 帮你逐帧读数、拟合曲线、挑出误差来源**。

## 怎么做

1. 木板一端垫高，量出斜面长度 `L` 和高度 `h`，`θ = arcsin(h/L)`。
2. 木板上每隔 10 cm 贴一道胶带当刻度。
3. 手机固定在侧面，开慢动作（240fps 或 120fps，**记下用的是哪个**），镜头正对斜面。
4. 小球从顶端**静止释放**（手要稳，别给初速度），拍 3 次。
5. 逐帧读出小球经过每个刻度的帧号，`t = 帧号 / 帧率`，`s` = 从起点到该刻度的位移。
6. 拟合 `s = ½at²`，得到 `a`。
7. 和理论值比（见下一节）。

## 先搞清楚：你的球是在滚还是在滑

这是这个实验最常见的错误，会差 30%：

| 运动方式 | 理论加速度 |
|---|---|
| 光滑滑块（纯滑动） | `a = g·sinθ` |
| 实心球滚动（无滑动） | `a = (5/7)·g·sinθ ≈ 0.714·g·sinθ` |

用弹珠、钢珠是**滚动**，别直接拿 `g·sinθ` 比。

**算个数**：`θ = 10°`，`g = 9.8`：

```
g·sinθ      = 1.70 m/s²
滚动球 a ≈ 1.21 m/s²
滚完 1 m 需要 t = √(2/1.21) ≈ 1.29 s
240 fps 下 ≈ 309 帧
```

## AI 可以怎么帮你

**1. 先算，再动手**
> "θ=10°、斜面 1 米、小球滚动，大概几秒到底？240fps 够不够？"

先知道要拍 300 帧，你就不会用 30fps 拍完才发现根本分不开。

**2. 让它写逐帧追踪脚本**

300 帧手数是折磨。把视频交给 AI：

> "这是我拍的小球滚下斜面的慢动作视频。写一段 Python（OpenCV），逐帧找出小球圆心坐标，输出 (帧号, x, y) 的 CSV。背景是木色，球是深色。"

**手数 300 帧 vs 让脚本跑 10 秒**，这就是"借助 AI"最实在的地方。

**3. 让它拟合、出图、算 R²**

> "这是 (t, s) 数据，拟合 s = ½at²，给出 a、R² 和残差图，并判断是否接近匀加速。"

**4. 让它做误差归因**
> "这个实验的误差来源有哪些？各自大概多大？我该优先改进哪个？"

它会告诉你：松手初速度、手机透视、滚动摩擦、斜面不直——以及哪一项量级最大。

**5. ESP32 升级版**

两个红外对管做光电门，测小球通过两点的时刻；或霍尔传感器 + 小磁铁。AI 写 Arduino 代码，把人工读数彻底去掉。

## 会看到什么

位置-时间曲线是抛物线；把 `s` 对 `t²` 作图，是一条过原点的直线。**这条直线就是"匀加速"的证据。**

## 坑

- 松手给了初速度 → 曲线不过原点，拟合出的 `a` 偏大。
- 手机没正对斜面 → 透视让位移比例失真。
- 帧率凭印象记 → 一定要看视频元数据。
- 木板有接缝 → 小球会颠一下，数据出现台阶。
- 用了滚动球却按 `g·sinθ` 验收 → 自己给自己判错。

## 想再往前一步

- 换 5 个角度，验证 `a` 与 `sinθ` 成正比。
- 换不同质量、不同材质的球，验证加速度与质量无关。
- 用粗糙表面制造滑动，对比滚动与滑动的差别。
- 把数据做成一条"伽利略当年会想看"的曲线。

## 安全

无。别从高处滚重球，别把斜面架在过道。
